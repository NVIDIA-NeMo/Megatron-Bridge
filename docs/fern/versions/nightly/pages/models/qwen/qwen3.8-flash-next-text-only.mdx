# Qwen3.8-Flash-Next Text-only

`AutoBridge.from_hf_pretrained("Qwen/Qwen3.8-Flash-Next", text_only=True)`
selects the standalone `Qwen4ExpForCausalLM` architecture and excludes vision
encoder/projector weights. Conversion uses `convert.sh import --text-only`.
The [VLM guide](qwen3.8-flash-next.md) records full-model conversion and image SFT.

The text recipe is **EARLY, UNOPTIMIZED**: the full 48-layer language model,
fixed sequence length 4096, 32 GB200 GPUs, TP2/SP, EP32/ETP1, PP1/CP1 and Muon.
Only EP-sharded PLE n-gram lookup tables are frozen; projections, normalization
and convolution remain trainable. Natural routing and HybridEP are enabled.
The input is a bounded one-million-token WikiText dataset, reused across 30 updates.

| Workload | GPUs / sequence / updates | Initial → final loss | Final-ten mean step | TFLOP/s/GPU | Token slots/s/GPU |
| --- | --- | --- | --- | --- | --- |
| Frozen-PLE text / Muon | 32 / 4096 / 30 | 1.927702 → 1.366627 | 3.637 s | 47.46 | 1126.30 |

Released NeMo 26.10 verification completed on 2026-11-22. All 32 ranks completed
finite, unskipped updates and frozen table hashes remained unchanged. Text-only
GPU import and native reload were exercised; an independent exact standalone-text
weight comparison and text-only export remain unverified. Full-VLM roundtrip
results do not qualify this distinct checkpoint namespace.

The [text-only verification card](../../../examples/model_verification_cards/qwen3.8-flash-next-text-only/card.yaml)
retains the original source revision, commands, dataset and metric definitions.
These are functional observations, not optimized benchmarks. TFLOP/s uses the
run's original analytical estimator, including a dense surrogate for 4K QSA;
it has not been recomputed with the newer model-local estimator. Training does
not establish inference, cross-framework trajectory parity or optimizer/RNG resume.

See the [training instructions](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/main/examples/models/qwen/qwen4_exp/README.md)
for separate checkpoint import and the registered recipe. The shared decoder's
[PLE sharding implementation and attribution](qwen3.8-flash-next.md#frozen-ple-table-sharding)
also apply to this mode.
